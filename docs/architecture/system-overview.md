# Elmtui System Architecture Overview

This document provides a high-level overview of the Elmtui system architecture.

## Major Architectural Components

Elmtui is composed of several key architectural layers and components:

1.  **Application Layer ([`app`](../modules/app/overview.md)):**
    *   Manages the overall application lifecycle.
    *   Handles top-level application state and events, and orchestrates the main program flow.

2.  **Core System ([`core`](../modules/core/overview.md)):**
    *   Provides fundamental services like the event loop, asynchronous operations, and the message bus.
    *   Manages focus and input handling.

3.  **State Management ([`state`](../modules/state/overview.md)):**
    *   Implements the state model (inspired by Elm architecture).
    *   Handles state updates based on messages.

4.  **UI Components & Widgets ([`ui`](../modules/ui/overview.md)):**
    *   Defines the building blocks for user interfaces.
    *   Includes a system for creating custom components (e.g., `defcomponent`) and a library of standard widgets.

5.  **View & Rendering ([`view`](../modules/view/overview.md), [`platform`](../modules/platform/overview.md)):**
    *   **View Definition ([`view`](../modules/view/overview.md)):** Provides a DSL for declaratively describing UI structure, layout (e.g., flex, grid), and styling (colors, text attributes).
    *   **Rendering Pipeline ([`platform`](../modules/platform/overview.md)):** Translates the abstract view representation (view tree) generated by the `view` module into terminal output. This involves:
        *   Potential tree diffing for efficient updates.
        *   Backend drivers for different terminal capabilities (e.g., basic ANSI).

6.  **Low-level Utilities ([`clevelib`](../modules/clevelib/overview.md), [`utils`](../modules/utils/overview.md)):**
    *   **[`clevelib`](../modules/clevelib/overview.md):** For C Foreign Function Interface (CFFI) bindings or other low-level system interactions (e.g., terminal control via `termios`).
    *   **[`utils`](../modules/utils/overview.md):** General utility functions and macros used across the library.

7.  **Development Support ([`dev`](../modules/dev/overview.md)):**
    *   Tools for debugging, monitoring, and introspection of Elmtui applications and the library itself.

## High-Level Data Flow

(A brief description or diagram illustrating how data and events flow through the system, e.g., input -> event -> state update -> view re-render -> terminal output.)
*   **Input:** The `platform` module captures raw terminal input (keyboard, mouse).
*   **Event Processing:** The `core` module receives this input, parses it into events, and dispatches them (often to the focused `ui` component).
*   **State Update:** `ui` components, upon receiving events or messages, may trigger updates in the `state` module. The `state` module applies update logic (model + message -> new model).
*   **View Generation:** Changes in state cause relevant `ui` components to re-generate their visual representation using the `view` module's DSL. This creates a "view tree."
*   **Rendering:** The `view` module's renderer (e.g., tree-renderer) processes this view tree. It may perform diffing against a previous tree to find minimal changes.
*   **Terminal Output:** The renderer instructs the `platform` module to send the necessary commands (ANSI sequences, text) to the terminal to reflect the new UI.

## Key Interactions

(Describe how major components interact, e.g., how UI components use the state system, how the view system uses platform backends.)
*   The `app` module orchestrates the startup, main loop (via `core`), and shutdown.
*   `ui` components are central, defining behavior (`update` logic via `state` principles) and appearance (`view` DSL).
*   The `core` module is the heart of event flow and focus management.
*   `state` provides the data model and update rules.
*   `view` translates component state and props into a renderable structure.
*   `platform` abstracts terminal I/O.
*   `clevelib` provides low-level access for `platform`.
*   `utils` offers common helpers to all modules.
*   `dev` hooks into various modules for debugging.
